# 社内 AI アシスタント開発ガイド

このガイドは、社内で Mastra を使って AI アシスタントを作るときの手順と決まりをまとめたものです。
第4章の RAG のサンプルは、このファイルをチャンクに分けてベクトルストアに登録し、検索の対象にします。

## 1. Agent の定義

Agent は `@mastra/core/agent` の `Agent` クラスで定義します。必須の項目は `id`・`name`・`instructions`・`model` の 4 つです。

- `id`: Agent を識別する文字列です。英小文字とハイフンで付けます（例: `support-agent`）
- `name`: 画面やログに表示する名前です
- `instructions`: システムプロンプトです。Agent の役割、回答の形式、してはいけないことを書きます
- `model`: 使用するモデルです。社内の標準は `anthropic/claude-sonnet-4-6` です

外部の処理を呼び出す必要がある Agent には `tools` を渡します。`tools` はオブジェクトで、キーが LLM に見える Tool 名になります。キーは用途が分かる名前にしてください。

会話の履歴を保持する Agent には `memory` を渡します。Memory の設定は `src/mastra/memory.ts` に 1 つだけ置き、複数の Agent で共有します。

## 2. instructions の書き方

instructions には次の 3 点を必ず書きます。

1. Agent の役割（誰の、どの作業を手伝うか）
2. 回答の形式（箇条書きか文章か、敬語を使うか）
3. 禁止事項（社外秘の情報を出さない、推測で答えない）

instructions にユーザーの入力をそのまま埋め込まないでください。プロンプトインジェクションの原因になります。ユーザーの入力はメッセージとして渡します。

長い社内規程を instructions に貼り付けると、呼び出しのたびにその分の入力トークンが課金されます。規程が長い場合は、本ガイドと同じように RAG の検索対象にします。

## 3. Tool の作り方

Tool は `@mastra/core/tools` の `createTool` で作ります。`inputSchema` と `outputSchema` は Zod で書き、各フィールドに `.describe()` で説明を付けます。

`description` には、何を入力すると何が返るかを具体的に書きます。「顧客情報を取得」ではなく「顧客 ID を指定して、名前・メールアドレス・契約プランを返します」のように書きます。

1 つの Agent に渡す Tool は 10 個までを目安にします。それより多くなる場合は、Agent を用途ごとに分けます。

## 4. エラーの扱い

Tool の `execute` で処理を続けられないときは、理由が分かるメッセージで例外を投げます。LLM はそのメッセージを読んで、引数を直して呼び直したり、ユーザーに状況を説明したりします。

例外を捕捉して `null` を返すような書き方は禁止です。LLM が失敗の理由を知ることができず、同じ呼び出しを繰り返します。

外部 API のレート制限（HTTP 429）は、Agent の `model` に予備のモデルを並べておくと、別のモデルに切り替えて処理を続けられます。

## 5. 個人情報の扱い

会話の履歴と Working Memory には、ユーザーが話した個人情報が保存されます。ユーザーから削除の依頼があった場合は、`src/scripts/gdpr-delete.ts` の `deleteUserData()` で、そのユーザーのスレッドと Working Memory を削除します。

ログとトレースにも個人情報が残ることがあります。本番では、トレースに送る前に個人情報を取り除く設定を入れてください。

## 6. リリース前の確認

リリースの前に、次の項目を確認します。

- Tool の単体テストと、テスト用のモデルを使った Agent のテストが CI で通っている
- 想定される質問を 10〜20 件用意し、検索結果に必要な情報が含まれているかを確かめた
- 本番の Memory の保存先が PostgreSQL になっている（開発用の LibSQL のファイルを使っていない）
- API キーがリポジトリに含まれていない
